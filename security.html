RFB security extensions

RFC 6143 gives RFB almost no confidentiality. VncAuth is a DES challenge, not a tunnel. OmniKali therefore authenticates at the gateway and keeps TigerVNC on loopback.

What we run

  • Google / X / email at the gateway (Better Auth).
  • One-shot RFB tickets on /ws/rfb. No ticket → 401.
  • Host-fwd 127.0.0.1:5901 → guest :5900. Not on 0.0.0.0.
  • Guest SecurityTypes None only behind that pipe, so noVNC does not prompt for a VNC password and status probes do not blacklist SLIRP.
